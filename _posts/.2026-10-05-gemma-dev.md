## This post contains the preliminaries that I came across while preparing for the Gemma4 Competition

Trying to understand what LoRA is and how it exactly works - so LoRA or low rank adaption is a technique which is used to alter only specific weight matrices in a given LLM and these are applied on the fly. And the fact that they alter the values of these weights very sparsely makes them extremely lightweight to ship along with the actual model.

Alright so when we think about updaing / post training - it is basically adding capabilities to the model that don't already exist - and instead of re-training the entire model to do it - we can just train a subset of numbers to alter the right weights and we want to learn this too in a Low-Rank fashion. Rank of a matrix basically defines the maximum number of linearly independent rows and columns. As a side note - if you really think about it, being linearly independent means that others cannot express you i.e. if a matrix is 3 dimensional and all the columns are linearly independent - two columns cannot represent the third no matter what we do. And geometrically we can think of this as the three columns being in totally separate directions, each just slightly different from the one preceding it. So LowRankAdaption basically means making changes to the weights of the model in such a way that the majority of the change is restricted to just a few dimensions/directions. HOW? What are the weight matrices inside a transformer / Neural Network? They can either be thought of as simple projecion or transformation operations - and when we change these weight parameters - learning change for each individual parameter gives us more refined control but can be prohibitive. So instead we focus on learning change in only a few direction - but our final change matrix that gets added to the original weight matrix must be same in dimension SOOO we leverage linear algebra, and instead of learning the change for each and every parameter in the weight matrix - we break it down and learn fewer actual nudges which then control the overall change.

For example, suppose we have a 1000 x 1000 weight matrix that we need to update:

We break down the change into two smaller matrices B and A whose shape is like: 1000 x 10 & 10 x 1000 (notice that multiplying these two sub-matrices still gives a 1000 x 1000 matrix) i.e. this way instead of learning 1000 x 1000 param changes, we only learn 1000 x 10 + 10 x 1000 = 20000 param changes. But when these two matrices are multipled, they do end up modifying all the 1000 x 1000 numbers. That's low rank adaption for you.

For the insanely curious, in the current gemma task too - we will be trying to do changes via LORA adapter and another interesting thing here was how exactly are these things used?
So the true weights of the model are simply frozen and the learned LoRA weights are then applied on top of the existing Wx + b calculation as Wx + A*B + b where A,B are the thin LoRA adapter weights that we are looking at.

### A side tangent on why loading models saved via pickle may lead to arbitrary code execution:

Models that are saved using pickle rely on a particular trick to be saved and also to be reconstructed. When saving the model, using torch.save() - Python uses it's pickle module under the hood in order to turn the model architecture and weights into a byte stream - and it must also specify the specific way in which the weights and the model architecture was encoded or converted into byte stream - so that the key details are known when the checkpoint is loaded again. And this in python is handled via the __recover__ special function - which python looks at and runs when trying the load the .ckpt or the .pt file. Which also means that malicious or rogue actors can possibly populate these functions with arbitrary code like `(os.run("curl...))` that could be disastrous.

So, to tackle this - what the .safetensors data type for model storage does is that they save the metadata and the relevant information about the moel as a JSON header and the rest of the importatnt information as continous bytestream - raw numbers so adding any payload as arbitrary code atleast becomes very difficult.
