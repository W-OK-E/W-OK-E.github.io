The authors state that instead of just increasing parameter count or depth of a transformer - which is one of the ways of improving it's performance - we can leverage the power of recurrence i.e. applying a certain operation again and again and reusing the components as much as possible instead of having several copies of that operation that are applied separately and effecitvely add to the total parameter count. The idea is to simulate depth in the model via repeated operations of the same component rather than having copies of that component in multiple places.

A straightforward and tried method so far for this has been weight sharing. Which they call "response to memory-depth coupling" i.e. allowing the effective depth to grow without inflating parameter count. And the drawback that the authors highlight here is that more often than not, these systems are used to match performance at either reduced parameter counts or to increase performance at matched parameter counts (I mean isn't that obv.?) Another thing is that standard weight sharing forces an identical transformation on ever-evolving representation.

What the above means is that:

In a normal transformation, layer 1 handles some aspect of the input, and layer 8 learns some other component, but when  you start sharing depth between layer 1 and layer 8 - this capacity to learn different representations also collapses. 

**But what does the depth of a transformer model mean in this case?** - The depth simply refers to the number of stacked layers. Just to be precise and to recall the structure of an LLM to get the large picture:

- A LLM is made up of multiple tranformer "blocks" - Each transformer block is made up of multiple attention heads - and each head has it's own Key, Value and Query which gets applied to every token sequentially. (Sequentially?)

Correction needed - during training the attention operation is "parallel" because the entire operation happens in one giant matmul, during generation you use a KV cache, and the way it works is:

You start with a seed token and it's value - and then start generating the key, value cache in each attention head via each attention head's Key, Value projection matrices - Then you take the current "value" of the token - and multiply the Query matrix with it to get the Query vector which is then compared with the Key vectors to see which one it attends to the most and then also modifies the Value vectors in the Key value cache?


So an LLM is made up of multiple transformer blocks and each transformer block is made up of multiple attention heads. What weight sharind does is that in this depth-wise manner - one transformer block is repeated (and the weights kept the same) - so for instance if there are 20 layers - it means each "layer" is a transformer block and each transformer block has it's own weights - now weight sharing essentially means - having the same transformer block in different layer positions.

Now the idea behind gated recurrent transformer is that now - the function/projection/operation at both layers 2 and 10 are identical and it falls to the hidden state now to carry more of the burden instead of the depth-wise specialization being learnt by the different layers of the transformer.

The Hidden state is essentially the model's current internal representation at a given layer and step - same old process of the input embeddings passing in, and attention beind computed by each block to modify the meaning.

Now usually, in a normal auto-regressive transformer with L blocks, the updates are still residual, i.e.

Hidden activation after layer i = Hidden activation before layer i + Layer_i(hidden activation before layer i)
