-  An interesting point that the paper raises is that agents/actors in an RL env don't really know about their own state - they only get the observations - and even though we say that the ideal agents directly observe the environment, it is hard to actuall estimate the current state. The agent reccieves the observation - which  is an approximation of the current state - and that observation is usually imperfect - partial or noisy and sometimes even redundant.

Now this fact should mean that the observations given to the agent from the environment should be meaningful enough that the agent can derive the environmental state for optimal decision making. WHich more often than note ends up meaning that we want to provide as much information as possible to the agent.

ANother interesting way of understanding and looking at why a sequence of observations is better than just a single observation would be that - from static images - the information about movement is lost and it is generally advantageous to provide a sequence of images or a video in that case. and interestingly enough, this can be applied to all sorts of partiaully observable information. 

When training agents on time-bound tasks - we can also pass the remaining time of a task as observation and the agent can learn time dependence. In real-world environments too, it is often useful to provide the current time as sine/cosine embeddings.


## Tangent towards positional encoding in transformers:

Okay without taking a lot of tangents in the topic, just one tangent:

If sine/cosine embeddings are used here to represent the fact of time being circular and closed, how and why are they used in the transformer architecture:

Positional embeddings in transformers are given by:

PE(pos,2i)=\sin\left(\frac{pos}{10000^{2i/512}}\right)

PE(pos,2i+1)=\cos\left(\frac{pos}{10000^{2i/512}}\right)


This basically means let's say that each token was represented by a 512-dimensional embedding, we generate a positional embedding of the same dimension with each element being sampled from either a sine or a cosine function - each with different frequency - and the frequency is decided by the position of the token + dimension where we are embedding it - then the next natural question that comes to mind here is that if in the end we are simply adding up the two embedding vectors - how does the model learn to make sense of the two separately? Well the model does not necessarily need to learn the meaning or representation of the positional and the token embedding, there are a few ways in which it can use that fact:
1. The embedding that goes into the model for processing is - tok + pos. Remember here that the token embeddings are learnt, while the positional embeddings that are derived mathematically are fixed. Soooo - imagine a token for the word "the" - it is definitely going to appear in tons of places in the data being fed - and the initial embedding for all of this (derived from a embedding matrix or bag of words) will be the same - these tokens will differ by the virtue of being at different positions in the text/data. So the model has a vantage point that lets it understand the positional aspect in some way. But then let's also look at how the attention operation is applied and how it works:

attn. score = (Q.K_T)@V [Here T is the transpose] then you think about how does one actually obtain these Q and K vectors:

Q = W_Q * E where E is the embedding of the token (e + p - plain emb + pos emd)

Now when you look at it: Q = W_q * (e + p) = W_q * e + W_q * p and 
K = W_k * e + W_k * p

attn. score = (W_q * e + W_q *p) @ (W_k * e + W_k * p) @ V -> and if you look at the first part of the equation:

W_q * e . W_k * e + (A)e.p + (A)p.e + (A)p.p - where A = (W_q . W_k) - here the entire way in which the attention score gets calculated ends up getting the positional and the semantic part talking to each other and hence the model technically has access to the relevant information required.

So we define a positional embedding factor of the same dimension and ensure that each individual element in that positional embedding is derived from a sine/cosine function of different frequency. In fact the even dimensions are all from sine functions + the odd functions are all from cosine functions. And this positional encoding vector - which is a mixture of sine/cosine function gets added to the embedding vector for each token.

### Critical points on reward design/engineering:

- One important thing that I think I did not think about when working with Quad-RL was HOW to design the reward function. One should try to identify and avoid loopholes in the reward function and be precise. For the agent to learn the policy, the agent must precisely learn the desired objective function to be achieved - and not be able to exploit the reward function. Basically the paper says that rewards MUST BE GIVEN TO THE MODEL ONLY IF IT ACHIEVES THE DESIRED OBJECIVES AND THROUGH THE DESIRED PATHWAY.


That begs the Question - doesn't that make the reward function very sparse - being sparse basically means that the moddel is getting rewarded for very few actions - which may make learning difficult? So the paper says that the final reward function should be as dense as possible - while ensuring that the intended goal of "not letting the model diverge too much from the final intended goal remains".

### Defining an episode

Episode definition matters and is important - and there are two aspects to this - termination and truncation : Termination happens when an agent successfully completes a given task while truncation happens when we want to limit an episode for whatever reasons - length of response OR for introudincg variability of in out test data etc.

Now internally - what happens in RL training is that when we terminate an episode - the step at which we are terminatng the episode gets it's value assigned to 0 i.e. since we are not going to explore those no matter what happens so the estimated value for the state where the env was agents are terminated, the value estimate that we put on that particular state just before terrminating the entire rollout should be 0 -  because that sends the signal to the agent that this is the final stage and that the rollout will end. But when we are talking about truncation - the value estimate of the final state must not be set to 0 - because we are just intervenining and terminating the rollout early - does not necessarily mean that whatever the agent would have explored after that state was entirely useless or something.
