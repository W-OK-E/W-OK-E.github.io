What we are trying to do:

- Generate 3D meshes using parameteric body models.
- Position these meshes in a virtual Unreal environment (Unreal Engine, not "unreal")
- Capture Snapshots from different angles and store the images along with the camera metadata that can be useful for us.

The end goal here is to have images and their corresponding 3D parameters to train an image to 3D model. However a few preliminary Questions arose in my mind and I needed to set them straight before training the pipeline or even generating data.

Q1. Where does the parametric model generate it's meshes?
- The parametric model is not conditioned on the surroundings of the environment it is a part of and only samples from the distribution of the respective parameters. But it still needs to predict the parameters relative to something, because they are 3D - and so it conveniently chooses the reference to be the pelvis i.e. the pelvis joint becomes the root joint and every joint angle and position of other joints are represented with respect to that.

Q2. Where does the Model we are training generate it's meshes / Outputs?
- THis is an interesting Question because I was very confused here personally. One thing to remember here is the fact that the model is learning to predict these parameters - so it can also learn WHAT FRAME IT MUST PREDICT IT IN. It's as simple as that.

Q3. So the model will learn whatever frame we put the data in, so what are all the things that need to be transformed into this frame that we will later target?
- Because we are dealing with parametric models, it is important to realize that not every parameter that we predict would require transformation. But for the ones that do require transformation - there are a few caveats that we must keep in mind:
    a. We are working with Unreal Engine and we will be importing the mesh in an environment at some location.
    b. Now, the pose parameters (angles of each joint relative to the root joint) and the shape parameters (betas or weights so to say that control how much certain sections of the body/mesh stretch squish and in what directions) are frame independent. Like think about this - the relative joint angle between the hooves and the belly will be the same for a static horse regardless of whether it's in Unreal or in some different game engine.
    c. Each mesh generated from the parametric model has a global orientation - which is also conveniently defined to be around the Root joint in axis-angle format (i.e. 3 numbers which tell you how much the mesh is rotated and by how much). And this is what we would also need to change if we want to represent everything in camera coordinates. What we would need to ideally do:
     i. If we have the relative rotation between the mesh's default axes (the root joint axes) we can directly transform the global orient to be represented w.r.t that axis.
     ii. But since we place the mesh in the world at arbitrary location, it would be difficult to know that and so we will have to figure out the relation between the horse's rotation and the world coordinate axes first and then transform all the way to the camera coordinate axes.
     ii. Parameters that need this transformation are the global orient of the parameteric mesh along with the location of the 3D joints. 
And with all the above arrangements, the entire objective is that the way the model learns to predict these parameters is in terms of "how far is the mesh from the camera, how is it rotated w.r.t to the camera, how large does it appear to the camera and so on and so forth."
